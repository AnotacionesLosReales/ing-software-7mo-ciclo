# Semana 5: Agile Project Schedule Management

## Intro

- Tradicionalmente, los projectos de software se han gestionado en un enfoque basado en habilidades/fases.

***Consideraciones para el enfoque Agile:*** 
- *La entrega es un compromiso entre el cliente y el equipo de entrega.*
- *El cliente proporciona al equipo una visión del producto y una hoja de ruta.*
- *Luego, el equipo determina una fecha de lanzamiento en función de un conjunto determinado de funcionalidades.*
- *O, también, puede elegir un set de funcionalidades para ser entregado primero dentro de un periodo de tiempo determinado.*

## Plan Schedule Management

- Los procesos de planificación de los proyectos son **iterativos** y suceden a lo largo del proyecto.
- La gestión del cronograma de planificación no es la creación del cronograma real del proyecto. Sino, define como llevar a cabo políticas y procedimientos del proyecto para administrar el cronograma.
- El proceso real de creación del plan de gestión del cronograma implica que el equipo del proyecto y otros expertos se reúnan para discutir y acordar políticas y procedimientos que deben tener los procesos de gestión del cronograma.
- También, puede incluir la identificación y aprobación de herramientas y técnicas que se utilizarán para programar y controlar el trabajo del proyecto.

***Consideraciones para el enfoque Agile:*** 
- *Los enfoques ágiles utilizan incrementos más cortos de trabajo del proyecto frenta a fases más largas que pueden existir en un entorno predictivo.*

## Define the Project Activities

- El cronograma tradicional del proyecto es la herramienta principal para medir el tiempo y desempeño del proyecto; el equivalente Agile es el **release plan**.
- En planificación tradicional, se suele definir una fecha de inicio y final para cada actividad.
- Los **release plans** en Agile determinan la fecha de fin de una actividad en base a la fecha de fin de una iteración.

### Release Plan

- Un release plan es un plan de alto nivel para una serie de iteraciones.
- Permite realizar un seguimiento del progreso iteración por iteración.

## Sequence the Project Activities

- El objetivo es determinar las relaciones entre las actividades y las dependencias que impulsan la secuencia.
- Antes de secuenciar, se debe determinar las dependencias.
- Existen cuatro dependencias que pueden impulsar el orden en el que se realiza el trabajo:
  - Obligatorio
  - Discrecional
  - Interno
  - Externo
- Las relaciones y sus dependencias proporcionarán una hoja de ruta del proyecto e inevitablemente afectarán la duración del mismo y sus recursos.
- Hay cuatro relaciones que se pueden usar en cualquier diagrama de red de procedencia:
  - Finish to start
  - Start to start
  - Finish to finish
  - Start to finish

***Consideraciones para el enfoque Agile:*** 
- *En Agile, la secuenciación la realiza el equipo en la planificación de la iteración y cambia a lo largo de la iteración en función de la sincronización diaria del equipo a medida que descubre más detalles sobre la creación de la funcionalidad.*
- *Durante la planificación, el Project Manager y el equipo conocen las fechas de inicio y finalización de la iteración*

## Estimate Activity Duration

- La estimación de recursos, en la gestión tradicional, se determina después de haber definido las actividades.
- En Agile, esto se invierte. Es decir, los miembros de un equipo (recursos) se determinan por adelantado y se dedican al proyecto.
